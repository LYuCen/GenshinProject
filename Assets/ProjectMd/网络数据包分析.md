## 二、二进制数据包格式

```
┌──────────────┬──────────────┬──────────────────────┐
│  4 bytes     │   2 bytes    │      N bytes         │
│  bodySize    │  MessageType │  FlatBuffers Payload │
│  (int32 LE)  │  (ushort)    │                      │
└──────────────┴──────────────┴──────────────────────┘
```

- `bodySize` = 2 + N（类型 2 字节 + 负载长度），不含自身 4 字节长度头
- 总传输大小 = **6 + N** 字节
- 套接字配置：`NoDelay = true`，发送/接收缓冲区 = 65536 字节

## 三、全部消息类型

### C2S（客户端→服务端）

| 枚举值 | 类型 | 说明 | 序列化方式 | 使用状态 |
|--------|------|------|-----------|---------|
| C2S_UpdatePosition = 1 | 位置同步 | 定义但**未使用** | — | ❌ 废弃 |
| C2S_PlayerShoot = 2 | 开火 | 射击数据 | FlatBuffers | ✅ 事件驱动 |
| C2S_PlayerHit = 3 | 命中请求 | 定义但**未使用** | — | ❌ 废弃 |
| C2S_Revive = 4 | 复活 | 无负载 | 空 | ✅ 事件驱动 |
| C2S_Move = 5 | 移动同步 | 位置+旋转+输入 | FlatBuffers | ✅ 20 Hz |
| C2S_Bones = 6 | 骨骼同步 | 骨骼旋转+瞄准点 | FlatBuffers | ✅ 10 Hz |
| C2S_StateChange = 7 | 状态变化 | 8 状态位域 | 原始 4 字节 | ✅ 事件驱动 |
| Both_Heartbeat = 200 | 心跳 | 客户端时间戳 | 原始 4 字节 | ✅ 3 秒间隔 |

## 六、架构关键特性

### 线程模型

```
TCP 后台线程 (ReceiveLoop)
    │
    │  UnpackMessage() → Message(type, data)
    ▼
ConcurrentQueue / lock(lockObj)
    │
    │  Unity 主线程 Update() 出队
    ▼
Listener.Dispatch() → 反序列化 → 游戏逻辑
```

### 服务端权威

- **命中验证：** 服务端 `RewindHitCheck` 在所有命中判定上具有权威性
- **时间偏移：** 服务端为每个客户端计算 `timeOffset = serverTime - clientSendTime - halfRtt`
- **延迟补偿：** 命中检测使用 `serverShotTime = clientTime + timeOffset`
- **无移动验证：** 服务端盲目信任客户端位置（无反传送/速度检查）

### 客户端插值

- `SnapshotBuffer`：32 个快照的环形缓冲区
- 插值延迟：100ms（渲染落后于服务器）
- 最大外推时间：200ms（超时后速度衰减到零）

### 优化点

- `ShootDataConverter` 和 `HitDataConverter` 复用 `static FlatBufferBuilder` 减少 GC
- Nagle 算法已禁用（`NoDelay = true`）
- 发送/接收缓冲区增大到 65536 字节
- 骨骼旋转压缩为 ushort（4 字节 → 2 字节每分量）
- `S2C_Position` 将所有玩家批量为单个 FlatBuffer 消息

### 已知问题

1. **文件名拼写错误：** `UnityServerManger.cs` → 应为 `UnityServerManager.cs`
2. **S2C_Bone（108）已定义但未实现：** 骨骼数据从不广播给其他客户端
3. **~~C2S_UpdatePosition（1）~~** 和 **~~C2S_PlayerHit（3）~~** 已定义但从未使用
4. **无服务端移动验证：** 客户端可以传送/加速而不被检测
5. **20 Hz 位置与 50 Hz 元素的定时器不一致：** 元素可能在位置更新之间发生变化
