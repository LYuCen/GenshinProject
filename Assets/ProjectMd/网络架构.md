# 网络架构

## 概述

网络系统支持**单机模式**和**联机模式**的双模运行。单机模式下使用 `LocalServerSimulator` 在客户端进程内模拟服务端逻辑；联机模式下通过 TCP 长连接与真实服务端通信。协议层使用 FlatBuffers 进行序列化，部分简单消息使用 `BitConverter` 直接编码。

## 核心组件

### 1. NetworkService — 网络服务入口

`MonoBehaviour` 单例，管理连接生命周期和双模切换。

```
Awake():
  if isSinglePlayer → StartSinglePlayer() → Bridge = LocalServerSimulator
  else              → ConnectToServer()   → 创建 UserClient + TCP 连接

Update():
  Connected     → Heartbeat.Tick()
  Reconnecting  → 计时重连
  按 T 键       → 单机切联机
```

关键职责：
- **Bridge 切换**：单机/联机的唯一差异点，上层代码通过 `NetworkService.Bridge` 发送消息，不感知底层是模拟器还是真实网络
- **状态机驱动**：`ConnectionStateMachine` 管理 Disconnected → Connecting → Connected → Reconnecting 的状态流转
- **心跳管理**：`HeartbeatService` 在 Connected 状态下驱动

### 2. INetworkBridge — 网络桥接接口

```csharp
public interface INetworkBridge
{
    void SendToServer(Message msg);  // 发送消息
    int GetMyId();                   // 获取本地玩家 ID
}
```

两个实现：

| 实现 | 适用场景 | SendToServer 行为 |
|------|---------|------------------|
| `LocalServerSimulator` | 单机模式 | 直接在客户端进程内模拟服务端逻辑，结果通过 `Listener.EnqueueMessage` 回到客户端 |
| `RealNetworkBridge` | 联机模式 | 委托 `UserClient.SendMessage()` 通过 TCP Socket 发送 |

### 3. UserClient — TCP 客户端

底层网络传输层。

```
连接:
  Socket(IPv4, TCP) → Connect(ip, port)
  NoDelay = true     ← 禁用 Nagle 算法
  BufferSize = 65536 ← 64KB 收发缓冲

发送:
  Message → [4字节总长 + 2字节Type + FlatBuffers data]
  Send() 阻塞发送（在 Unity 主线程外风险可控，数据量小）

接收:
  后台线程 ListenLoop:
    Receive(4字节头) → 解析 bodySize
    Receive(bodySize) → UnpackMessage → OnMessageReceived 事件
```

**二进制包格式：**

```
┌────────────┬────────────┬──────────────────────┐
│ 4 bytes    │ 2 bytes    │ N bytes              │
│ 总包体长度  │ MessageType│ FlatBuffers 数据      │
│ (小端序)    │ (ushort)   │                      │
└────────────┴────────────┴──────────────────────┘
```

### 4. Listener — 消息分发中心

挂载在场景中的 `MonoBehaviour`，管理线程安全的消息队列。

```
后台线程 → EnqueueMessage(msg)  [lock 保护]
主线程 Update → Dequeue → Dispatch(msg)  [lock 保护]
```

`Dispatch()` 根据 `MessageType` 分发到各个业务处理逻辑，包括：
- 玩家管理（AllocId, Spawn, Exit, Death, Revive）
- 状态同步（Position, StateChange, Hp, AllPlayerInfo）
- 战斗相关（PlayerShoot, DamageConfirm）
- 元素系统（ElementAttach, ElementDetach, StatusEffect）
- 心跳（Both_Heartbeat）

### 5. ConnectionStateMachine — 连接状态机

```
Disconnected ──Connect()──→ Connecting ──OnConnectSuccess()──→ Connected
     ▲                          │                                  │
     │                          │ OnConnectFailed()                │ OnConnectionLost()
     │                          ▼                                  ▼
     │                      Disconnected                    Reconnecting
     │                          ▲                                  │
     │                          │ 超过最大重试次数                   │
     │                          │                                  │
     └──────────────────────────┘                                  │
                                                          OnConnectSuccess()
                                                                   │
                                                                   ▼
                                                              Connected
```

配置参数：
- `MaxReconnectAttempts = 5`：最多重连 5 次
- `ReconnectInterval = 2s`：重连间隔 2 秒

### 6. HeartbeatService — 心跳服务

```
Tick():
  每 3s → 发送心跳包 (携带客户端时间戳)
  超过 10s 无消息 → OnTimeOut

OnHeartbeatResponse():
  RTT = Time.time - 客户端发送时间
  更新 LastReceiveTime

OnAnyMessageReceived():
  更新 LastReceiveTime  ← 任意业务消息也视为心跳存续
```

RTT 计算：`当前时间 - 心跳发送时的时间戳`（简化方式，未做服务端时间差修正）。

## 同步系统

### PlayerPool — 玩家对象池

管理所有在线玩家的 `PlayerManager` 实例（Key = PlayerId）：

```
RegisterLocalPlayer(id, pm)     ← 本地玩家注册
SpawnRemotePlayer(dto)          ← 创建远端玩家 GameObject
UpdatePlayer(list)              ← 全量更新（HP + 位置 + 旋转 + 动画状态）
UpdatePositions(list)           ← 仅位置旋转更新（高频）
ApplyHp / ApplyRevive           ← 血量和复活
DeletePlayer(id)                ← 玩家下线清理
```

### SnapshotBuffer — 快照插值缓冲

用于远端玩家的平滑渲染，避免网络抖动导致的视觉跳变：

```
Head ─→ [t0] [t1] [t2] ... [t31] ←─ 环形数组 (最多32个快照)

AddSnapshot(pos, rot, vel):
  存入当前快照 + 根据前一帧计算速度

TryGetInterpolated(renderTime, out pos, out rot):
  renderTime = Time.time - InterpolationDelay (默认100ms)
  在快照数组中二分查找 renderTime 所在区间
  使用 Lerp/Slerp 插值
  超出最新快照 → 用速度外推 (最多200ms)
```

### RemotePlayer — 远端玩家渲染组件

挂载于远端玩家 GameObject：

```
OnServerUpdate(pos, rot, inputMove, aimPos):
  → SnapshotBuffer.AddSnapshot()
  → 同步 inputMove 和 aimPos 到 PlayerStateData

Update():
  → TryGetInterpolated(renderTime - 100ms)
  → 设置 transform.position/rotation
```

### SyncChannel — 同步频道（暂未启用）

按频率分频上报的抽象基类：

| 频道 | 频率 | 上报内容 |
|------|------|---------|
| `MoveSyncChannel` | 20Hz (50ms) | 位置 + 旋转 + 输入方向 |
| `AnimSyncChannel` | 10Hz (100ms) | 移动状态位掩码 + 武器状态位掩码 + 姿态 + 瞄准点 |

`PlayerSyncManager` 管理频道列表，按各自间隔调用 `TrySend()`。目前代码中已被注释，改用更简单的 50Hz 全量采样 + 20Hz 批量发送。

## 输入同步流程（联机模式）

```
客户端 (50Hz ClientTick):
  ┌──────────────────────────────────────────────┐
  │ SampleInput():                                │
  │   tick++                                       │
  │   inputX/Y = MoveModule.GetMoveInput (映射0-255)│
  │   yaw/pitch = cameraController (×10 量化)      │
  │   holdButton = 累积的按键位掩码                 │
  │   → _pendingSamples.Add(sample)                │
  └──────────────────────────────────────────────┘

客户端 (20Hz):
  ┌──────────────────────────────────────────────┐
  │ SendInputPacket():                            │
  │   sequence++                                   │
  │   InputDataConverter.Pack(sequence, samples[]) │
  │   → C2S_PlayerInput → Bridge.SendToServer()   │
  │   _pendingSamples.Clear()                     │
  └──────────────────────────────────────────────┘

服务端:
  接收 InputPacket → 解析多个 InputSample
  每个 InputSample → 驱动服务端模拟一帧
  定期回执 → S2C_Position / S2C_Reconcile
```

**输入位掩码 (PlayerInputStateBoolBit)：**

| 位 | 按键 |
|----|------|
| BIT 0 (1) | Jump |
| BIT 1 (2) | Crouch |
| BIT 2 (4) | Sprint |

### Converter 层

将 FlatBuffers 的 Pack/Unpack 封装为静态方法：

| 文件 | 功能 |
|------|------|
| `InputDataConverter` | 输入采样 Pack/Unpack |

- FlatBuffers：复杂嵌套结构（玩家状态、位置列表、输入包）
- BitConverter：简单固定长度数据（AllocId、PlayerExit、Hp、Revive）

## 单机模式 (LocalServerSimulator)

在 `LocalServerSimulator` 中模拟了服务端的核心逻辑：

```
SendToServer(msg) → HandleServerLogic():
  C2S_PlayerShoot → ReceiveAtClient(msg)          // 直接回传
  C2S_PlayerHit   → UpdateInternalBotState()      // 扣血
                    + PackAllPlayers()             // 打包全量数据
                    + ReceiveAtClient()            // 回传
  C2S_Revive       → 复活对应玩家
  Local_AddBot     → CreateFakeBot()              // 创建 Bot
```

每次处理完消息后都会调用 `PackAllPlayers()` + `ReceiveAtClient()` 发送全量玩家状态，模拟服务端的周期性状态广播。

## 数据流总览

```
单机模式:
  LocalPlayerLogic.OnClient50HzTick()
    → SampleInput() → _pendingSamples
  LocalPlayerLogic.OnClient20HzTick()
    → SendInputPacket()
    → Bridge.SendToServer()
    → LocalServerSimulator.HandleServerLogic()
    → Listener.EnqueueMessage(S2C_AllPlayerInfo)
    → Listener.Dispatch() [下一帧 Update]

联机模式:
  LocalPlayerLogic.OnClient50HzTick()
    → SampleInput() → _pendingSamples
  LocalPlayerLogic.OnClient20HzTick()
    → SendInputPacket()
    → Bridge.SendToServer()
    → RealNetworkBridge → UserClient.SendMessage()
    → TCP 发送到服务端
    ...
    → TCP 接收 → UnpackMessage → OnMessageReceived
    → Listener.EnqueueMessage()
    → Listener.Dispatch() [下一帧 Update]
```

## 关键设计决策

### 1. 双模 Bridge 模式

单机和联机通过 `INetworkBridge` 接口切换，上层业务代码不感知模式差异。好处是单机模式可以脱离服务端独立开发调试，联机时零改动切换。

### 2. 消息队列线程安全

`UserClient` 在后台线程收包，通过 `lock` 保护入队；`Listener.Update()` 在主线程出队处理。避免了 Unity API 的跨线程调用问题。

### 3. 禁用 Nagle 算法

`Socket.NoDelay = true` 确保小包（如玩家输入、心跳）不会因为 TCP 的 Nagle 合并延迟发送，降低输入延迟。

### 4. FlatBuffers 零拷贝

FlatBuffers 的优势是无需反序列化整包即可访问任意字段。当前实现中使用 `ByteBuffer` 包裹 byte[] 后直接 `GetRootAsXXX()`，没有额外的解析开销。

### 5. 多种编码方式混用

简单消息（AllocId、PlayerExit）直接用 `BitConverter` 编解码，复杂嵌套结构用 FlatBuffers。在性能和可维护性之间取平衡。

### 6. 插值渲染缓冲

`SnapshotBuffer` 故意落后 100ms 渲染，用这段时间窗口收集足够快照进行平滑插值。当网络抖动导致快照缺失时，使用速度外推（最多 200ms），超出后冻结位置，避免玩家出现瞬移。
